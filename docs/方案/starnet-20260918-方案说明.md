# starnet-20260918.zip 方案实现思路与算法流程

## 1. 对象与边界

本文说明实际提交包 [`submissions/starnet-20260918.zip`](../../submissions/starnet-20260918.zip) 的实现，不把未打包的研究脚本当作提交逻辑。包的 SHA-256 为 `e643b36711591c8f3e31a52db80ff0587f1df8277ca9904cf167307c18f5a543`；根目录只有 `config.json`、`starnet_model.py`、`prompt/commander.txt`、`prompt/reflect.txt`。

赛题是部分可观测网络干预：先以扫描获取节点倾向、人设和邻接信息，再在精神力预算内游说或屏蔽，最终由官方环境完成共识演化并评分。该方案不读取隐藏图、不推断官方精确共识公式；已知图仅用于构造候选，**最终执行哪些动作以及动作顺序由 CaseVO 指挥 Agent 调用注入的大模型决定**。`prompt/reflect.txt` 随包提供，但当前执行流程不调用它，也不产生额外的反思或嵌入请求。

## 2. 包内分工与状态

| 组成 | 职责 |
| --- | --- |
| `config.json` | 配置一名“反馈驱动的星网指挥官”及其职责说明；没有配置其他智能体。 |
| `starnet_model.py` 中 `ObservationBook` | 保存已扫描/已屏蔽节点、观测属性、话术反馈及校准目标；产生公开信息可支持的候选和启发式分数。 |
| `CommanderAgent(AgentBase)` | 通过 `commander.txt` 和 CaseVO 的 `send_prompt` 向注入 LLM 请求 JSON 计划。 |
| `ParticipantSquadModel(ModelBase)` | 管理阶段、预算与调用上限，验证 LLM 计划，每次 `step()` 最多执行一个合法环境动作。 |
| `prompt/commander.txt` | 要求模型比较扫描、话术与屏蔽的机会成本，只从候选编号选择；允许空列表主动停机。 |

运行时优先导入线上旧名 `agent_mesa`，仅在该模块不存在时回退到本地 `casevo`；使用 `networkx.Graph` 初始化框架模型并注册指挥 Agent。节点数默认由初始预算推断为初赛 50 / 复赛 100，测试角色配置可覆盖 `node_count`（范围 1 至 100）。初赛的步数和 LLM 调用各至多 120，复赛各至多 250，分别计数，而非共享一个额度。合法环境交互限于 `get_remaining_budget`、`scan_node`、`communicate`、`shield_node`；本包**不调用 `cut_link`**。

## 3. 决策与执行流程

1. **取状态并守住额度。** 每次 `step()` 先检查是否停止、步数是否达到上限，随后读取剩余精神力；余额低于 2 则停止。只有无待执行计划时才构造候选并请求 LLM。每次请求前再检查独立的 LLM 调用上限。
2. **探索阶段 `explore`。** 只要还有未扫描 ID 且余额至少 2.5，候选就是未知节点。优先排序被已知节点邻接表指向次数较多的未知节点，同分按 ID 升序；最多展示 16 个候选，由 LLM 每批批准至多 8 个**不同节点**的扫描。单次扫描花费 0.5，结果校验后记录 `w`、`persona`、`comm_left` 和已知邻居。此处保留至少 2 点预算供后续实质干预，并不保证扫描到所有节点：余额不足或模型主动停止均会结束探索。
3. **话术校准 `calibrate`。** 若尚无校准目标，从剩余沟通次数、和平人设、邻居数排序的已知节点中取前四个，向模型提供每个节点的 1/2/3 号话术候选。模型一次只批准一项；首次成功游说确定校准节点。之后在该节点上依次选择尚未测试的话术，每次获得反馈后重新询问模型，直到三种编号测完或该节点不可再游说。编号的实际效果不是事先写死的。
4. **干预阶段 `intervene`。** 从已观察为正向的已测话术构造游说候选；游说候选按估计效用排序截取前 12 个，同时给模型最多 4 个满足 `w < -20`、已知邻居数至少 3 的屏蔽候选。一次游说计划至多涉及 4 个不同节点；若选择屏蔽，则该计划只能有这一个动作，执行后清空计划并重算拓扑候选。没有候选或模型返回 `choices=[]` 则停机。
5. **逐步兑现与反馈。** LLM 仅输出候选索引列表和非空理由；模型代码检查索引、批次长度、目标是否重复、预计总成本及动作合法性。执行每一项前重新读取预算、复核目标与剩余沟通次数；成功扫描、游说、屏蔽才更新观测本。游说若实际增量非正，或与候选估计偏差超过 `max(1, |估计| × 0.5)`，取消剩余批次，下次交由 LLM 重规划。一次 `step()` 只执行一个动作并返回继续/停止状态。

简化路径：`公开观测 → 生成有限合法候选 → LLM 授权计划 → 每步再校验 → 执行一个动作 → 记录反馈 → 继续或重新规划`。这不是按固定 if-else 自动下达游说/屏蔽指令：算法负责信息整理、候选过滤与风险提示，模型负责选项和顺序。

## 4. 候选评分的含义

对话术 `p` 在节点 `v` 的一次成功沟通，记录实测变化 `delta = new_w - old_w`。若它是该节点第 `k` 次沟通（`k=1,2,3`），按题目给出的边际系数 `0.5^(k-1)` 归一化为 `normalized_gain = delta / 0.5^(k-1)`，以便比较不同编号。预测另一候选时，依次使用同节点同话术样本中位数、同人设样本中位数，最后才使用跨人设的经验比例（和平 1、中立 0.65、暴力 0.2、其他 0.5）；**这些比例只是排序先验，不是官方隐藏人设系数**。

游说估计增量 = 归一化收益估计 × 目标当前沟通轮次衰减；候选 `utility_proxy = 估计增量 × (已知邻居数 + 1) / 2`。只保留收益估计为正的话术。屏蔽的 `utility_proxy = -w × (已知邻居数 + 1) / 5` 只是负面负担提示，**不是删点后的边际得分预测**：删点也会断开邻居连接，可能损害正向传播。度数来自已发现邻接表，未扫描节点不能提供精确的全图度数。模型提示词因此要求比较屏蔽风险与游说机会成本。

## 5. 保护措施与局限

- `scan` 还要求至少 2.5 预算；`comm` 要求已扫描、`comm_left > 0`、话术编号为 1/2/3 且预算至少 2；`shield` 要求已扫描、`w < -20`、邻居数至少 3 且预算至少 5。重复扫描、重复计划目标、不可支付的批次和无效反馈均不继续执行。
- LLM 响应必须是带非空 `reason` 及 `choices` 列表的 JSON。无效计划最多再请求一次；55 秒超时立即停止，未另起并行补救请求。环境动作请求不自动重试；异常只在内存审计中记录类型，不打印可能含凭证的异常文本。
- 校准的三次沟通可能本身产生负收益，尤其当未知话术实际为负时；屏蔽阈值是保守候选过滤，不保证收益。空计划和无可用正向话术时可保留预算停机。包内没有切边策略或精确求解共识演化的算法。
- `llm_calls` 是该程序发起的调用数；注入客户端内部重试是否产生额外计费/调用，必须由平台计量确认。

## 6. 验证记录与结论

现有[研究报告](../../research/starnet-strategy/report.md)记录：9 个自建种子的 36 次**无 LLM 算法对照**用于选型，不能当作最终提交成绩；同一个 ZIP 在独立的自建 10/50/100 节点种子上，使用真实 CaseVO、真实本地 LLM 和官方公开沙盒运行，三次干预分数分别为 77.27、139.43、579.05，自然分分别为 -75.28、-995.01、-574.83；LLM 调用分别为 8/20/35，步数分别为 23/87/174，剩余预算分别为 1/0/1。不同规模不能混算为官方榜单平均分。项目另记录 25 项 Python 3.9 契约/打包测试通过及独立解压校验。

**结论：** 这是“公开图探索 + 同节点反馈校准 + 启发式候选 + LLM 最终授权 + 逐动作复核”的实现。上述分数只对应自建种子与本地所用模型；线上旧版 `agent_mesa`、官方指定 GLM 和隐藏种子的 `PlayerAvg ≥ BaseAvg` 尚未由平台验证，不能据此宣称正式有效完赛或隐藏种子泛化效果。复现细节见[研究决策](../../research/starnet-strategy/decision.md)与[研究报告](../../research/starnet-strategy/report.md)。
