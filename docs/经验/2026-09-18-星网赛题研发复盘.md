| 首轮调用 `/api/evaluate` 后再查预算，返回 HTTP 404。 | `evaluate` 会结束该 session，结算后不能继续查询。调整为**先记录余额，再触发结算**，重跑完整基线；参见[基线记录](../../research/starnet-strategy/runs/20260918-213312-baseline/results.md)。 | 给远端会话建立明确状态机；任何终结性 API 后不要继续读取旧 session。 |

## 可复用的工作方法

1. **先定证据级别和验收门槛。** 静态检查、Python 3.9 框架替身测试、Python 3.12 真实 CaseVO、官方公开沙盒自建种子、天池隐藏种子是不同证据。初赛/复赛各自有独立的步数与 LLM 调用上限；没有隐藏 `PlayerAvg` 和 `BaseAvg`，就不声称正式有效完赛。
2. **每次策略对照固定种子和预算。** 按同一组种子分别跑自然演化、固定策略、反馈策略和结构策略，记录种子、初始预算、得分、剩余预算、步数、LLM 调用、HTTP 请求、耗时与峰值内存；失败局单独报告。论文中的共识或子模近似只能提供启发，官方精确演化方程未知。
3. **把权限检查与决策授权分开。** 本地算法生成有限、可支付的候选，大模型选择编号与顺序，代码再逐动作核验；每个执行动作对应批准的计划。对于无效 JSON 最多重问一次，超时或环境反馈不确定时停止，不改由硬编码动作继续。
4. **将本地测试工具与提交文件隔离。** 本地超时 HTTP 客户端、种子生成器、`.env`、日志和测试依赖都不进入 ZIP。只从源码构建白名单文件，校验 Python 3.9 语法、密钥、哈希和独立解压加载；禁止通过反射读取环境隐藏状态。
5. **在小主机上串行、可复现地实验。** 使用[受限脚本](../../scripts/run_limited.sh)限制为单核、2.5 GiB 虚拟地址空间和 600 秒，设置 HTTP 超时并记录原始日志。先试小图，再试 50/100 节点；超过资源门槛就停机记录，不无限重试。
