## 2. 证据分层

整个研发过程首先区分了五类不能互相替代的证据：

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 静态检查、导入和 Python 3.9 语法 | 包结构、接口名、基本兼容性 | 策略有效、线上可启动、隐藏分数 |
| 框架替身单元测试 | 授权、预算、失败停机、动作路由等代码契约 | 真实 CaseVO 行为、网络服务、模型决策质量 |
| 本地代理模拟 | 快速筛选候选、构造反例、检查预算规划 | 官方共识引擎的精确得分 |
| 官方公开沙盒自建种子 | 官方同源结算对指定自建网络的结果 | 官方隐藏分布、榜单分数、官方 GLM 表现 |
| 官方隐藏种子平台 | 是否有效完赛、真实平均分及是否达到 950 | 无替代证据；必须取得平台回分 |

这一划分贯穿所有结论：导入成功不是策略证明；自建种子超过 950 也不是官方目标
达成；本地 `gpt-5.6-luna` 的结果不能替代官方 `glm-4-plus`。

## 3. 执行过程

### 3.1 规则、协议与研发边界

先阅读赛题、补充规则、FAQ 和原始 SDK，确认以下硬约束：

- 初赛 50 节点、100 精神力，步数和 LLM 调用分别最多 120 次；复赛对应
  100 节点、200 精神力和 250 次上限。
- 只能调用 `get_remaining_budget`、`scan_node`、`communicate`、`cut_link`、
  `shield_node` 五个环境 API。
- 必须使用 CaseVO/旧版 `agent_mesa` 的 `AgentBase`，核心动作需由 LLM 真正参与，
  不能以纯图算法直接替代决策。
- 线上话术编号效果、人设响应系数和精确共识公式均为黑盒。
- ZIP 根目录只能包含 `config.json`、`prompt/` 和 `starnet_model.py`。

原始 `SMP_Starter_Kit/` 保留为参考，没有修改外部 CaseVO 仓库。研究客户端、种子、
日志、`.env`、测试依赖和原始实验输出均不进入提交包。

### 3.2 V1：建立可运行、可审计的反馈策略

V1 依次完成 Prepare、Specify、Baseline、Explore、Compare、Decide、Apply、Review：

| 阶段 | 执行内容 | 结论 |
| --- | --- | --- |
| 协议基线 | 用带超时的客户端验证建局、预算、扫描、游说和结算 | 建立会话状态机，不能沿用旧 SDK 的 50 步占位规则 |
| 选型矩阵 | 种子 21-26（10 节点）、31-33（50 节点），每种运行自然、固定话术、反馈校准、反馈加屏蔽，共 36 局 | 固定话术会在编号排列变化时退化；反馈校准显著更稳健 |
| 策略设计 | 完整扫描、同节点三话术校准、度数和人设生成候选、LLM 批准有限计划 | 图算法整理公开信息，LLM 决定动作和顺序 |
| 防护设计 | 每步最多执行一个动作；执行前复核预算和状态；坏 JSON 最多重问一次；超时停机 | 不使用未经 LLM 授权的硬编码兜底动作 |

### 3.3 V2 重新规格化：从 531.1233 面向 950

950 相对 531.1233 需要约 `78.8662%` 的官方分数提升。分析 V1 后发现两个主要
瓶颈：

1. 游说只按“倾向增量 × 度数”排序，没有比较结构操作后的全局边际收益。
2. 屏蔽只估计被删节点的负面负担，没有计算删点对邻居、连通分量和剩余游说预算
   的影响；切边则完全未启用。

因此 V2 的研究问题被明确为：能否从公开扫描图中构造一个足够准确、但不冒充官方
公式的分数代理，用它生成屏蔽、切边和游说机会成本候选，再由 LLM 最终选择。

### 3.4 共识影响探针

先在 `path5`、`star6`、`cycle6`、`clique5`、`barbell7` 和 BA9 六类小图上，
仅将一个节点初始值设为 10，其余为 0，通过官方沙盒结算测量节点单位响应。38 次
探针、76 个 HTTP 请求、0 步动作、0 次 LLM 调用全部完成。

观测结果与以下经验代理在结算舍入范围内一致：

\[
\widehat S=\sum_C |C|\frac{\sum_{i\in C}(d_i+1)w_i}
{\sum_{i\in C}(d_i+1)}.
\]

探针 MAE 为 `0.00112`，最大误差 `0.00486`。这反证了 V1 将未归一化
`degree+1` 直接用于结构比较的做法，但只支持“经验代理”，没有证明官方引擎就是
该数学公式。

### 3.5 V2 原型、消融与留出比较

V2 原型对每个结构候选执行以下计算：

1. 模拟屏蔽节点或切断已知边，重算所有连通分量和影响权重。
2. 计算结构操作的即时 `gain_proxy`。
3. 从剩余预算中选择可购买的游说序列，计算相对直接游说的
   `completion_advantage`。
4. 以未来游说收益 0.5、1、1.5 倍计算 `robust_advantage`，只作为 LLM 风险信息。

主要比较结果：

| 实验 | 旧启发式 | V2 原型 | 配对结论 |
| --- | ---: | ---: | --- |
| 开发集：6 个官方沙盒 50 节点种子 | 122.4167 | 168.9583 | 6 胜，均值 +46.5417 |
| 留出集：6 个官方沙盒 50 节点种子 | 636.7650 | 666.4450 | 4 胜 1 平 1 负，均值 +29.6800 |
| 额外 18 个本地代理种子 | 607.1704 | 638.6145 | 12 胜 4 平 2 负 |

50 节点最终状态上的代理误差：开发集 MAE `0.5106`、最大 `2.1512`；留出集
MAE `0.3322`、最大 `1.7317`。

消融和失败方案同样保留：

- 自动选择低度节点校准只有 2 胜 4 负，拒绝采用。
- 纯屏蔽在断连图上丢失切边收益，保留合法切边候选。
- 强制使用最坏情形过滤，在 24 个模拟场景中相对名义规划 6 胜、9 负、9 平，
  平均只增加 `1.3289`，最差退化 `42.4549`，因此不作为硬规则。
- 官方留出种子 135 上，V2 原型从 `1804.12` 降至 `1781.58`。该反例说明
  分数代理准确不等于未来话术响应估计准确，必须把不确定性暴露给 LLM，而不是
  强制执行所有正边际结构动作。

### 3.6 V2 实现

最终选用名义预算规划，并将不确定性作为建议字段提供给 LLM：

- `policy.py`：公开观测、话术反馈归一化、计划校验。
- `topology.py`：连通分量影响、屏蔽/切边重算、剩余游说预算估计。
- `model.py`：CaseVO 编排、LLM 调用、逐动作执行、断边路由、失败停机。
- `commander.txt`：要求比较即时边际、预算完成优势、压力优势和置信度。

每个节点只展示当前最强的已测正向话术，避免前 12 个候选被同一节点的多个话术
占满。结构动作必须单独批准，执行后清空旧计划并重算；没有结构候选时，LLM 可批准
最多 4 个不同节点游说。V2 允许低度负节点屏蔽和合法切边，但不自动执行。

### 3.7 真实 LLM 同种子配对

旧、新 ZIP 在相同自建种子、相同本地 `gpt-5.6-luna`、真实 CaseVO 0.3.19、
Python 3.12.3 和官方公开沙盒下独立运行：

| 种子 | 自然分 | V1 | V2 | 提升 | LLM 调用 V1/V2 | 步数 V1/V2 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 120 | -310.81 | -37.19 | 243.98 | +281.17 | 19 / 22 | 88 / 78 |
| 124 | -879.07 | -26.03 | 88.67 | +114.70 | 20 / 33 | 87 / 78 |
| 134 | 764.23 | 2061.44 | 2061.44 | 0 | 19 / 19 | 88 / 88 |
| 均值 | -141.8833 | 666.0733 | 798.0300 | +131.9567 |  |  |

配对结果为 2 胜 1 平，均值提升 `19.8111%`。V1 在种子 120 中执行 37 次游说、
没有屏蔽；V2 执行 20 次游说和 7 次屏蔽。种子 134 的正面网络中，V1/V2 都只做
37 次游说，没有为了使用结构算法而删图。

全部确认动作均能对应到 LLM 批准队列，动作成本与剩余预算一致，调用和步数均未
超限。该配对证明 V2 改善了这 3 个自建种子上的本地模型决策，不能外推为官方
隐藏分提升 19.81%。

## 4. 遇到的错误、定位与处理

| 现象或错误 | 定位与处理 | 可复用经验 |
| --- | --- | --- |
| 原始 SDK 使用旧的 50 步/调用上限，无远端超时，并出现规定外环境方法 | 以现行赛题和 FAQ 为准，独立实现 120/250 双计数、合法 API 检查和有界超时 | 示例代码只证明接口形状，规则文档才定义当前约束 |
| `uv run` 尝试写只读的 `/home/ubuntu/.cache/uv` | 统一设置 `UV_CACHE_DIR=/tmp/smp20260918-uv-cache` | 在受限环境显式固定可写缓存，避免把文件系统问题误判为策略失败 |
| `/api/evaluate` 后继续查询预算返回 HTTP 404 | 确认 `evaluate` 会销毁 session；改为先记录余额，再结算 | 给远端协议建立状态机，终结操作后不再读取旧会话 |
| 写请求出现 `RemoteDisconnected`，随后只读请求也失败 | 状态可能不确定，丢弃整局，使用新 session 重跑；增加 `Connection: close` | 可能已经生效的修改请求绝不自动重试；失败局不以零分混入均值 |
| 首次 V1 真实配对在第 10 步出现 `ReadTimeout` | 该局只完成 9 次扫描，无干预；保留日志并排除，重新建局。只读 `get_budget` 最多重试一次，修改 API 不重试 | 重试策略必须按幂等性分类；“网络失败”不能自动等价为“动作未执行” |
| 固定 prompt 1 在部分种子中降低得分 | 话术编号效果随种子排列，改为同节点探测三个编号，并按沟通轮次衰减归一化 | 黑盒动作先做小成本校准；不能把样例编号语义写死 |
| 自动屏蔽在部分种子中退化 | 保存退化种子，改为重算图结构和剩余游说机会成本，最终仍由 LLM 选择 | 结构动作需计算对全局和后续预算的影响，不应只看目标节点当前值 |
| 留出种子 135 中分数代理准确但策略仍退化 22.54 | 问题来自未来话术响应估计，不是拓扑公式误差；加入压力指标，但拒绝强制最坏情形过滤 | 模型误差需按来源拆分；状态价值准确不代表动作后未知响应准确 |
| 强制保守过滤在 24 场景中 9 次退化 | 筛选阶段即否决，未进入最终实现；压力值只作为 LLM 风险提示 | 保守规则也需要对照验证，不能因“看起来安全”跳过实测 |
| 低度节点校准 2 胜 4 负 | 拒绝自动低度校准，保留原同节点反馈流程 | 节省高影响节点沟通次数并不一定抵消低质量校准节点的估计误差 |
| 跨 Python 3.9/3.12 生成的浮点末位不同 | 对需要稳定的字段做固定精度，并以固定 JSON 和 SHA-256 比较 | 可复现实验应固定输入文件，避免依赖浮点求和末位 |
| 研究脚本恢复运行时可能用新参数覆盖同编号种子 | 增加已有 JSONL 中种子哈希校验；参数变化必须使用新输出目录 | 可恢复实验必须同时校验 ID 和内容哈希，不能只按编号跳过 |
| 检索到的 arXiv 编号实际是无关量子论文；Crossref 模糊搜索也返回无关条目 | 核对题名、作者、摘要和 DOI；错误来源剔除，不进入方案依据 | 论文编号和搜索排名不是证据，必须核验原始元数据 |
| PyPI 查询不到 `agent_mesa` | 仅记录公网源情况，不据此断言官方环境缺包；本地和线上运行时分开验证 | “无法公开安装”“本地可导入”“评测机可运行”是三种不同事实 |
| 邮件在沙盒中返回 `401 Failed to get token` | 使用宿主现有 keyring 后 Gmail 返回 `SENT`；未输出或修改凭证 | 认证失败先判断所属环境；`SENT` 只证明提供商接受，不证明已读或平台已提交 |

## 5. 可复用的研发方法

### 5.1 先写规格和决策门槛，再改最终策略

research-lab 每轮先建立 `plan.md`，定义输入、种子角色、指标、资源限制、胜负门槛和
证据边界；完成比较后再更新 `decision.md`。开发集、历史留出集和新留出集必须标记，
一旦查看失败案例并据此调参，该集合就不再是新留出数据。

### 5.2 使用同种子、同预算的配对实验

每个候选都应与自然演化和当前基线共享完全相同的 JSON 输入，并记录：

- 种子 SHA-256、节点数、初始预算和话术配置角色；
- 最终分数、剩余预算、步数、LLM 调用和 HTTP 请求数；
- 耗时、峰值 RSS、停止原因和动作构成；
- 失败接口、失败类型及该局是否进入统计。

均值之外必须报告胜/平/负、最差退化和反例。中断局单列，不能按零分、自然分或
上一次结果填充。

### 5.3 用小图探针识别结构，再用大图和动作后状态验证

当官方公式隐藏时，可以使用公开 API 构造单位响应、小型对称图和断连图，逐步排除
错误模型。小图拟合通过后，还必须在未见拓扑、任意权重和实际干预后的图上测误差。
任何经验公式都应标注适用范围，不套用论文中的近似保证。

### 5.4 将候选生成、LLM 决策和动作执行分层

推荐架构为：

`公开观测 → 有限合法候选 → LLM 选择计划 → 逐动作复核 → 执行 → 记录反馈 → 重规划`

算法负责压缩公开状态、计算边际和过滤非法动作；LLM 负责选择候选和顺序；执行层
再次检查预算、节点、边和沟通次数。这样既满足 LLM 核心参与要求，也能审计每个
动作的授权来源。

### 5.5 重试必须服从幂等性

- `get_budget` 这类只读请求可以有限重试并记录失败。
- `scan` 会扣预算，不应在结果不确定时直接重试。
- `communicate`、`shield`、`cut` 可能已经改变状态，绝不自动重试。
- `evaluate` 会终结会话，失败后不能继续把旧 session 当作有效实验。

### 5.6 提交源码、研究工具和凭证严格隔离

最终 ZIP 由白名单构建器从 `src/starnet/` 生成，验证：

- 根目录成员精确等于 `config.json`、`prompt/*`、`starnet_model.py`；
- Python 3.9 语法和独立解压导入；
- 环境 API AST 白名单；
- 包内和改动文件中的本地凭证值扫描；
- 两次构建字节一致，记录最终 SHA-256。

研究客户端、代理模拟器、测试种子、`.env` 和原始日志不进入包。V2 最终构建与已交付
ZIP 逐字节一致，40 项测试通过，83 个改动/新增文件的本地凭证值扫描无命中。

### 5.7 在小主机上串行、受限、可恢复地运行

所有重实验通过 `scripts/run_limited.sh` 串行执行：单核、线程数 1、最长 600 秒、
虚拟地址空间上限 2.5 GiB。先跑小图和代理模拟，再跑 50 节点官方沙盒，最后才跑
100 节点真实 LLM。每个动作后保存审计检查点；JSONL 支持按种子和策略恢复，但恢复
前必须核对输入哈希。

## 6. 最终沉淀

本轮最重要的结论不是某个单种子分数，而是以下可复用判断：

1. **黑盒话术必须反馈校准。** 固定编号在话术排列变化时不可泛化。
2. **结构干预必须比较全局边际和机会成本。** 当前节点很负或度数很高，不等于删点
   一定优于继续游说。
3. **连通分量归一化影响比未归一化度数更适合结构比较。** 但它仍是经验代理。
4. **LLM 的有效性高度依赖候选质量。** V1 与 V2 使用同一类本地模型时，提供明确的
   结构边际后，模型才愿意在负面网络中执行有收益的屏蔽。
5. **稳健规则本身也可能过度保守。** 应把不确定性作为决策信息，而不是未经验证的
   强制阈值。
6. **失败实验是正式证据。** 超时局、退化种子和被否决的消融方案必须保留，才能
   避免重复走回死路。
7. **本地高分不能映射到官方分数。** 只有官方隐藏多种子回分能证明 950 目标。

V2 续研与 Review 阶段累计完成 80 次无 LLM 官方沙盒探针/控制、8 次成功真实 LLM 运行，
另有 1 次失败尝试单列；成功真实运行共 202 次 LLM 调用。平台交接邮件已获得
Gmail `SENT` 回执，但这不代表收件人已读、V2 已上传或官方已经评测。
