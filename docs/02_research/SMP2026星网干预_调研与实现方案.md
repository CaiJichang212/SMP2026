# SMP 2026 星网干预：背景调研与可执行实现方案

检索与核验日期：2026-09-05。依据：用户提供的 `task-spec.md`、任务书指定的官方示例仓库、casevo 源码、论文原文及 NetworkX 官方文档。

**建议方案：以 casevo 编排三个协作智能体，用 LLM 处理探索取舍、模型不确定性和策略切换，用图算法与数值模型评估动作，再以滚动规划执行“观测—决策—干预—更新”。先完成全图扫描与收益分配基线，再用实测证明自适应探索和结构干预的增益。**

首版落地配置：全图扫描、三个 Agent、每个决策步最多一次常规 LLM 调用；校准通过后加入深度 2、宽度 4 的结构规划；自适应扫描作为后续增强。快速阅读可先看第 2 节接入问题、第 4 节架构、第 7–10 节执行设计及第 12 节实施顺序。

本方案区分三类内容：**已确认规则**来自任务书或明确源码；**条件性推导**只在列出的数学假设下成立；**工程建议**是待实验选择的实现方案。当前公开资料不足以确认真实结算方程，因此不能宣称已经得到官方最优策略或正式评测成绩。

## 1. 任务的准确理解

### 1.1 实际优化问题

本题是**部分可观测、预算受限、终局奖励的网络意见优化问题**。图结构和节点属性需要通过付费扫描获取；行动修改的是最终演化开始前的网络状态。

与任务书叙事对应，必须分清：

- **参赛智能体**：由 casevo 编排、由官方注入的 GLM 驱动，负责侦察、分析、决策和执行。
- **星网节点**：50/100 个被模拟的个体，具有人设、倾向值和网络位置；不等于需要创建 50/100 个参赛 LLM 智能体。
- **动态干预**：依据新增观测和已执行动作动态调整策略。任务书描述的共识演化发生在干预结束后，不能假设每执行一步，负面观点就已经传播一轮。
- **优化目标**：存活节点终态的度数加权总和。不是正面节点数量、简单平均倾向、删除负面节点数量，也不是传播覆盖率。

用真实但起初不可见的状态表示为：

$$
s_t=(G_t,w_t,p,r,c_t,B_t),\qquad
b_t=P(s_t\mid o_{1:t},a_{1:t-1}).
$$

其中，`p` 是人设，`r` 表示可能存在但未必公开的个体响应参数，`c` 是剩余游说次数；`b_t` 是对未知信息的估计，不是已知事实。完整 POMDP（部分可观测马尔可夫决策过程）求解过于复杂，实际使用结构化状态、少量情景样本和有限深度规划近似。

终局目标写为：

$$
\max_\pi\ \mathbb E_{\text{隐藏种子},\,\pi}
\left[F(G_T,w_T)\right],\qquad
F(G,w)=\sum_{i\in V(G)}q_i(G)\,x_i^*(G,w).
$$

`q_i` 代表官方所说的“度数权重”。其具体函数、是否使用干预后度数，以及孤立节点权重，必须核验，不能自行用 `degree` 或 `degree+1` 定死。

### 1.2 约束与实现映射

| 事项 | 初赛 | 复赛 | 实现要求 |
|---|---:|---:|---|
| 节点总数 / ID | 50 / 1–50 | 100 / 1–100 | 阶段配置显式提供，不能沿用示例中的 4/5 个节点 |
| 精神力 | 100 | 200 | 本地按 0.5 为一个整数单位核算，并与环境返回值同步 |
| 扫描 | 0.5 / 次 | 同左 | 扫描一个节点得到其属性和所有有效邻接链路 |
| 游说 | 2 / 次 | 同左 | `prompt_id ∈ {1,2,3}`，每节点最多 3 次 |
| 游说边际系数 | 1、0.5、0.25 | 同左 | 按已成功游说次数计，不按模型尝试次数计 |
| 切边 | 3 / 次 | 同左 | 删除已知两节点之间的双向连线 |
| 屏蔽 | 5 / 次 | 同左 | 删除目标节点及其关联边 |
| 环境 Step 熔断 | 120 | 250 | 与 LLM 调用上限分别计数，任一触及即结算 |
| LLM 调用熔断 | 120 | 250 | 正式限制不由自定义种子的 `max_api_calls` 改变 |
| 停止 | 预算耗尽或主动结束 | 同左 | 按任务书在 `step()` 返回非 0，不臆造停机 API |

这里的步数估算按“每次外部 `step()` 至多执行一个付费环境动作”设计。预算查询、失败调用、底层重试是否另行计数，需要以正式评测器定义确认；本地另记 `env_calls`，不要混用 Step、环境 HTTP 请求数和 LLM 请求数。

### 1.3 评分对策略的影响

正式原始成绩是多个隐藏种子的 `PlayerAvg`。因此，开发阶段优先比较**同一组种子上的平均原始分及相对自然演化的分差**，不要在每个种子上先计算相对百分比再平均，那会改变优化目标。

任务书将 30 分完赛基准分和 70 分策略博弈分分开说明。给出的公式：

$$
70\cdot\frac{\mathrm{PlayerAvg}-\mathrm{BaseAvg}}
{\mathrm{MaxAvg}-\mathrm{BaseAvg}}
$$

对应后者，不能误作完整百分制总分。`MaxAvg=BaseAvg` 时的处理未明确，不自行实现官方天梯边界。达到相同原始分时，先比较剩余精神力，再比较 API 次数；因此不应为了用完预算执行零收益操作。

### 2.2 目前不能确认的机制

仓库公开的是调用远端服务的 SDK，不是完整的离线星网环境。`api_client.py` 的 `trigger_eval()` 请求服务器的最终标量分数；仓库文件树没有提供相应服务端结算实现。因此尚不能确认：

1. 共识方程、自保留权重、邻居影响权重、同步/异步更新、终止阈值和最大迭代次数。
2. 度数权重的具体函数，删除后的重算规则，以及孤立节点和空图如何计分。
3. 正式话术数值、响应系数是否逐节点变化、是否存在倾向上下限或额外副作用。
4. 扫描失败、重复动作、通信失败和各层重试的扣费及计数语义。
5. 正式评测的 Python / casevo / Mesa / ChromaDB 版本、可用数值库、墙钟时间限制和注入 LLM 的完整接口。

这些未知项会改变最优动作。研发可以先完成架构、状态机和测试框架；**精确评分器与不可逆结构干预的默认启用，需要通过官方说明或开发沙盒校准。**

### 2.3 样例参数的正确用途

公开自定义种子包含 `prompts={1:15,2:10,3:-5}`，并为不同和平节点设置 `r=1.5`、`r=1.2`；扫描示例没有保证返回 `r`。[样例种子](https://github.com/raoneng26/SMP2026/blob/75e896fb137d850f76c44eab2f14c38b6df59d3a/SMP_Starter_Kit/custom_seeds/my_test_network.json)

这说明应当：

- 将上述值作为**这个测试种子**的数据，不能推广为正式评测的固定常数。
- 不把人设直接等同于精确响应系数，更不能把游说响应系数 `r` 等同于共识模型中的固执程度。
- 将 `prompt_id` 当作预设动作编号；让 LLM 编写更有感染力的自然语言，不会自动改变该 API 的数值效果。
- `original_total` 只作为种子字段处理；未确认其语义前，不当作自然演化后的 `BaseAvg`。

2026-09-14 重新核对本地 FAQ Q4 后确认：正式话术修正值明确为黑盒，需要根据节点反馈学习。此前 P8/P9 的提交都固定使用话术 1，实验又几乎固定样例话术表；这是策略与实验覆盖的实际缺口，但仅凭官方总分相同，仍不能证明正式话术 1 一定不是最优。完整验证应在同一图与节点属性下置换话术编号，并独立改变话术幅度；策略只看公开反馈，不读取实验种子中的话术表或 `r`。

同节点的公开响应除以累计沟通衰减 `1,0.5,0.25`，可在未截断且节点响应系数为正的机制下比较话术排序。这只能辨识相对强弱，不能分别恢复绝对话术强度和节点 `r`。预测后续收益应维护所选话术的经验首轮等效响应；同一节点的三次探测不算三个独立敏感度样本。零响应、负响应、并列最优、截断及失败均需专门测试。

P11 初步机制实验的 72/72 最优编号识别与平均 `+287.390954` 来自双方都承担六次探测的匹配对照，**不是相对原始无探测 P9 的净收益，也不是官方成绩预测**。完整策略必须另与原始 P9 比较，报告探索预算、话术 1 原本最优时的损失、各编号排列的收益，以及相对已知最优编号诊断对照的差距。证据见 [P11 机制报告](../../experiments/reports/p11-prompt-calibration-result-20260914.md) 与 [公共衰减观测](../../experiments/reports/p11-prompt-order-probe-20260914.json)。

## 3. 背景资料与算法选型

### 3.1 对本题最有用的研究

| 方向与资料 | 可借鉴的内容 | 本题适用边界 |
|---|---|---|
| [Casevo，2024 预印本](https://arxiv.org/abs/2412.19498) | Agent 编排、记忆、环境交互 | 作为规定框架；论文的社会模拟能力不等于本题结算规则 |
| [ReAct，ICLR 2023](https://arxiv.org/abs/2210.03629) | 把推理、动作、观察交替组织起来 | 用结构化候选和真实 API 反馈形成闭环，不让模型凭空推断执行结果 |
| [Reflexion，2023](https://arxiv.org/abs/2303.11366) | 将失败反馈转成可复用的简短经验 | 记录真实接口错误和预测偏差；终局分数未返回时不能编造奖励反馈 |
| [意见动力学干预综述，2026-03-11 预印本](https://arxiv.org/abs/2603.10756) | 按优化目标和干预类型整理意见修改、结构修改、易感性修改 | 本题最相关的是总体意见最大化；极化最小化等目标只作理解参考 |
| [Wang 等：修改内在意见以最大化总体意见，NeurIPS 2025](https://arxiv.org/abs/2510.17226) | 以动力学对应的结构影响系数计算节点增益；研究采样与异步精确选点 | 其完整已知 FJ 网络、固定数目选点不等于本题的迷雾与混合动作；借鉴影响系数，不直接搬结论 |
| [Kempe、Kleinberg、Tardos：影响力最大化，2015 扩展版](https://theoryofcomputing.org/articles/v011a004/) | 边际增益选点、单调次模条件下的近似理论 | IC/LT 等扩散模型的覆盖率目标不等于连续意见加权和；不能声称本方案自动有 1−1/e 保证 |
| [VoteRank，2016](https://arxiv.org/abs/1602.00070) | 通过削弱已选节点周边投票，产生分散候选 | 主要证据来自 SIR 传播；在固定线性意见模型下，不应随意对相邻游说节点扣“覆盖重叠”分 |
| [Collective Influence，2015](https://www.nature.com/articles/nature14604)；[2016 实现论文](https://www.nature.com/articles/srep30062) | 用多跳结构寻找影响网络连通性的节点 | 连通性破坏不等于援助意愿提高，只作屏蔽候选生成器 |
| [Golovin、Krause：自适应次模性，JAIR 2011](https://arxiv.org/abs/1003.3967) | 理解部分观察下“获得信息再决策”的价值 | 本题的删点、切边和混合预算没有经过次模性证明，采用自适应贪心只能视为启发式 |

2025–2026 年资料对本题最有价值的启示是：**围绕真实动力学和终局目标计算动作边际收益，比继续叠加通用中心性指标更有针对性。**本题只有 50/100 个节点，先使用直接数值求解；百万级图的采样加速、GNN（图神经网络）和强化学习训练不是第一阶段的必要投入。

### 3.2 图指标各自负责什么

| 指标 | 用途 | 不能据此断言 |
|---|---|---|
| Degree（度数） | 局部连接数量、候选筛选、计分权重输入 | 度数最高就是最值得游说或屏蔽 |
| PageRank（网页排名算法） | 随机游走型结构特征 | 默认阻尼 0.85 就是官方共识方程 |
| k-core（核分解） | 发现高连接密度核心 | 核心必然传播更多正向或负向意见 |
| Betweenness（介数中心性） | 发现最短路径上的桥接位置 | 真实意见按最短路径传播；高介数边一定应切断 |
| VoteRank（投票排序） | 候选分散、减少纯度数排序的集中偏向 | 邻近游说一定收益重叠，或者已返回所有节点 |
| Community（社区）与连通分量 | 组织未知区域探索、构造拓扑反事实 | 已观测子图中的社区和桥就是全图真实结构 |

实现优先使用 NetworkX 已有接口：[PageRank](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.link_analysis.pagerank_alg.pagerank.html)、[介数](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.centrality.betweenness_centrality.html)、[核分解](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.core.core_number.html)、[VoteRank](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.centrality.voterank.html)。

`w` 是节点倾向，不能作为 NetworkX 的边长或边权。尤其最短路径算法的 `weight` 表示距离，不是观点正负。`voterank()` 返回的是节点序列，可能只包含部分节点；空图、无边图应有备用排序。[VoteRank 源码](https://github.com/networkx/networkx/blob/main/networkx/algorithms/centrality/voterank_alg.py)

## 4. 总体系统设计

### 4.1 三个 Agent，加确定性的计算内核

| Agent | 主要职责 | LLM 使用方式 |
|---|---|---|
| `ScoutAnalystAgent`（侦察分析） | 整理观测、维护图、估计未知信息、生成扫描和干预候选 | 大部分为 Python；疑难态势提交给指挥 Agent |
| `CommanderAgent`（策略指挥） | 选择探索/干预/停止，判断不确定性，比较动作组合，提出重新分析要求 | 使用官方注入 LLM，输出结构化策略与候选选择 |
| `ExecutorAgent`（执行反馈） | 参数和预算校验、单动作执行、结果解析、事件记录、触发重规划 | 通常无需 LLM；异常解释可交由指挥 Agent |

图算法、数值求解器、预算优化器是 Agent 可调用的工具，不假装每个工具都是一个需要独立推理的智能体。三个 Agent 必须实例化并通过 `add_agent` 注册，输出实际进入决策链；不能只继承框架类却运行固定动作列表。

注意保留两张不同的图：`agent_graph` 描述上述三个角色的协作关系，传给 casevo；`observed_starnet` 描述环境中已观测的星网节点，参与图算法。两者的节点 ID 和作用不能混淆。

~~~mermaid
flowchart TD
    O["公开 API 观测"] --> B["状态黑板"]
    B --> A["图分析与干预收益"]
~~~

### 4.2 状态黑板与证据边界

最低限度维护：

~~~text
observed_nodes[id]: w, persona, comm_left, neighbor_ids, last_observed_step
frontier_ids: 已出现在邻接表中、但尚未扫描的节点
unseen_ids: 合法 ID 中完全未被观察到的节点
observed_edges: 规范化无向边 (min(u,v), max(u,v))
confirmed_non_edges: 已扫描邻接表能够排除的边
shielded_ids / nonexistent_ids / unresolved_ids: 分别维护
response_estimates[id]: 预期响应、区间、样本次数、估计依据
resource_state: budget_units, outer_steps, llm_attempts, env_calls
event_log: 动作、实际返回、预算变化、状态版本
plan_state: 策略、候选、依赖条件、失效条件
~~~

“未知”不能填成 `w=0`、“中立”或“没有边”。将其作为属性未定的节点占位；已扫描节点的完整邻接表与后续成功结构动作足以维护其**当前精确度数**，即使邻居还未扫描。未扫描节点的已见连接数只是度数下界。

在“扫描返回完整有效邻接表、干预期无外生拓扑变化”的条件下，未知边只可能位于两个尚未扫描的存活节点之间。情景补全不能给已扫描节点添加违背其邻接表的新边。

### 4.3 每次执行后的状态更新

- **scan 成功**：录入真实属性和邻接表；合并边与已知非边；检查 `comm_left`，不重置为 3。
- **communicate 成功**：以返回的 `new_w` 更新倾向；返回剩余次数时优先采用，否则在已知成功时减 1；用实际 `Δw` 更新响应估计。
- **cut 成功**：删除该无向边，更新双方邻接集合及度数，废弃相关结构分数缓存。
- **shield 成功**：删除节点和所有已知关联边，更新邻居度数，重新计算受影响分量，废弃引用该节点的计划。
- **失败或返回无法判定**：不把预测当成成功；预算以公开查询校准。不盲目重发非幂等的游说操作，必要时通过允许的扫描核对次数和倾向。

`scan_node()` 的有效 `None` 返回可按接口语义记录为不存在/已删除；通信异常、JSON 解析异常不能伪装成这个返回值，也不能据此把正常节点永久拉黑。

## 5. 评分模型：先辨识，再计算干预收益

### 5.1 开发阶段的最小校准实验

通过 SDK 明确支持的**自定义测试种子**和独立开发会话开展实验；只使用官方允许的接口。参赛 `step()` 内不调用 `trigger_eval()`、不重置会话、不读取隐藏种子，也不访问服务器内部状态。

先用 4–8 节点微型图区分机制，再在 50/100 节点未参与拟合的测试图上验证。建议实验顺序如下：

| 实验 | 控制变量 | 需要判定的问题 |
|---|---|---|
| 常数意见 | 路径、环、星形、无边图都令 `w_i=c` | 是否保留常数意见；加权总分对应多少总权重；孤立点是否计分 |
| 单节点扰动 | 同一图，只改变一个节点的初始倾向 | 节点对最终总分的敏感度；是否线性、是否有截断 |
| 同度数不同位置 | 匹配度数但改变社区和桥接位置 | 影响是否仅由度数决定，还是取决于全局结构 |
| 相同图与倾向，不同人设/`r` | 只改变一个属性 | 人设和响应参数是否也参与最终动力学 |
| 三次连续游说 | 相同节点、相同话术；重新建图比较 | 1/0.5/0.25 是否按成功次数生效，是否存在倾向上限 |
| 结构干预对照 | 同一原始图，分别不动、切一边、删一节点 | 删除后的度数权重、分量和孤立节点行为 |
| 重复及失败请求 | 仅在专用开发测试中 | 扣费、幂等性、计步、停止和重试语义 |

这些是待执行的实验计划。本次未连接官方测试服务器，也未使用付费 LLM 做正式跑测。

**只有终局标量分也有用。**若固定图上的目标为仿射形式 `F(G,w)=b+hᵀw`，则在合法倾向范围内选基点 `w₀` 和扰动 `δ`：

$$
\widehat h_i=
\frac{F(G,w_0+\delta e_i)-F(G,w_0)}{\delta}.
$$

一次基点和 `n` 次单坐标实验即可估计这张小图的目标敏感度。再用不同 `δ`、不同基点和双坐标扰动检验线性及交互项。正负扰动须满足官方允许范围；每次都使用独立测试会话。

这**不能唯一恢复完整的节点演化方程**：不同动力学可能产生相同的最终标量。工程上优先辨识“足够预测动作收益”的模型；微型图拟合后还必须通过结构干预和留出图检验，不能凭少数匹配就认定官方采用某一模型。

### 5.2 候选 A：带自保留的 DeGroot 模型

下面是根据标准意见模型进行的任务化推导，**不是官方已公开结算公式**。基本模型定义可参见[意见动力学综述](https://arxiv.org/html/2603.10756)。

设 `A` 为无向邻接矩阵，`d_i` 为当前度数，`P=D⁻¹A` 为邻居平均矩阵；孤立节点单独处理。带自保留系数 `a_i` 的形式为：

$$
x^{(k+1)}=T x^{(k)},\qquad
T=\operatorname{diag}(a)+(I-\operatorname{diag}(a))P.
$$

对每个连通分量 `C`，若对应转移矩阵不可约且非周期，则存在稳态分布：

$$
\pi_C^T T_C=\pi_C^T,\quad
\mathbf1^T\pi_C=1,\quad
x_C^*=\mathbf1\,\pi_C^T w_C.
$$

令 `Q_C=∑_{j∈C}q_j`，该分量的总分和节点边际影响系数为：

$$
F_C=Q_C\pi_C^T w_C,\qquad h_i=Q_C\pi_i.
$$

因此，固定图下提升某节点 `Δw_i` 带来的终局增益是 `h_iΔw_i`。不连通图逐分量求解；孤立点按照实测到的权重和保留规则处理。

对无向无权图，且所有非孤立节点满足 `0≤a_i<1`，平稳权重满足：

$$
\pi_i\propto\frac{d_i}{1-a_i}.
$$

例如，若条件性地取 `a_i=d_i/(d_i+1)`，则权重正比于 `d_i(d_i+1)`，并非简单正比于度数。这里展示的是“自保留机制会改变节点价值”，不是给官方补造参数。

若没有自环或其他非周期条件，二部图上的纯同步平均可能振荡；不能只用一个无上限 `while` 等待收敛。实际评测若使用固定轮数 `K`，就应匹配有限轮数目标：

$$
F_K=q^T T^K w,\qquad h_K=(T^K)^Tq.
$$

不得用无限时域稳态结果冒充有限轮数结算。

### 5.3 候选 B：Friedkin–Johnsen 模型

FJ（弗里德金—约翰森）模型每轮保留一部分固定的内在意见；这与 DeGroot 每轮保留上一轮意见不同。其任务化形式写成：

$$
x^{(k+1)}=R w+(I-R)P x^{(k)},\qquad
R=\operatorname{diag}(\rho_i).
$$

这里 `ρ_i` 越大，固定内在意见的权重越大。它与种子中的游说响应参数 `r_i` 是两个变量，不能混用。只有当游说实际修改的 `w` 就是该模型的内在意见时，下面的游说收益推导才适用。若游说仅改变瞬时表达意见，必须重新推导其长期效果。[FJ 相关原文](https://arxiv.org/html/2510.17226v1)

当谱半径 `ρ((I−R)P)<1` 时：

$$
Q=I-(I-R)P,\qquad Qx^*=Rw.
$$

计算总分可直接解线性方程，不需要显式求逆。若要得到全部节点对总分的影响系数，只需解一个转置系统：

$$
Q^Tz=q,\qquad h=Rz,\qquad F=h^Tw.
$$

工程实现为：

~~~python
Q = np.eye(n) - (1.0 - rho)[:, None] * P
z = np.linalg.solve(Q.T, score_weights)
h = rho * z
predicted_total = h @ opinions
~~~

`rho`、`P` 和 `score_weights` 都必须来自已校准模型与观测/显式估计。这个片段不构成已经实现的官方模拟器。

对固定图、非负传播矩阵、非负计分权重，且游说只使内在意见增加的 FJ/DeGroot 候选模型，`h_i≥0`，正向游说不会降低模型总分。若这些假设尚未验证，只能称作保守候选，不能保证真实评测一定不低于基准。

### 5.4 一个决定策略方向的重要特例

**以下公式仅适用于：无向无权图、固定同一自保留比例的线性 DeGroot、计分使用干预后的 `q_i=d_i`，孤立点权重为 0，且没有其他截断或归一化。**

这时度数加权意见在演化中守恒：

$$
F(G,w)=\sum_i d_iw_i.
$$

由此得到精确动作分差：

$$
\Delta_{\mathrm{comm}(i)}=d_i\Delta w_i,
$$

$$
\Delta_{\mathrm{cut}(u,v)}=-(w_u+w_v),
$$

$$
\Delta_{\mathrm{shield}(i)}=-d_iw_i-\sum_{j\in N(i)}w_j.
$$

这是本方案的条件性代数推导。它说明“阻断负面传播”的叙事不能代替目标函数：在该特例中，高介数边并不会仅因处于桥梁位置而获得额外切断收益。

**反例**：星形图中心倾向为 −1，四个叶子均为 +10。初始分为 `4×(−1)+4×10=36`；屏蔽中心后四个叶子均孤立，得分为 0。删除负面中心反而损失 36 分。

这个反例不是对官方环境的实测结论，而是证明“负面核心 → 必须屏蔽”不能成为无需校验的通用规则。如果开发校准确认了这个特例，就启用这些廉价精确公式，避免不必要的共识迭代；否则使用对应模型重算反事实。

### 5.5 模型未能完全辨识时

保留少量通过开发数据检验的候选模型，而非把所有可能公式平均。每个模型保存版本、适用范围、验证误差和可信权重。

- **已校准模式**：使用直接数值评分或已验证的闭式公式。
- **有限不确定模式**：在多个可信模型及未知状态情景上计算动作增益，用均值和分歧辅助选择。
- **未校准模式**：优先验证正向游说，默认关闭自动切边/屏蔽；可以完成交互基线，但不宣称有分数保证。

如果候选模型对结构动作的增益符号都不一致，继续补充相关观测或选择其他动作。模型集覆盖不了真实机制时，集成方法也无法提供可靠保证。

## 6. 关键节点识别与动作收益

### 6.1 从“重要节点”转为“值得采取某动作的节点”

同一节点同时具有三个不同价值：

$$
\text{游说价值}_i\approx h_i\times\text{可增加的倾向},
$$

$$
\text{屏蔽价值}_i=F(G\setminus i,w_{-i})-F(G,w),
$$

$$
\text{扫描价值}_i=\text{观测后决策改善}-\text{扫描机会成本}.
$$

人设用于预测可游说程度，当前 `w` 用于判断真实倾向，结构影响系数用于衡量终局贡献。和平节点不必然当前为正，暴力节点也不应只凭标签进入删除队列。

### 6.2 游说：响应估计与边际递减

若校准支持“话术强度×个体响应×次数衰减”，候选增量为：

$$
\widehat{\Delta w}_{i,p,k}=g(p)\widehat r_i\gamma_k,
\qquad(\gamma_1,\gamma_2,\gamma_3)=(1,0.5,0.25).
$$

有倾向上限时，应先对实际可达新值截断，再计算 `Δw`。若机制不支持乘法分解，就直接维护 `(persona, prompt_id, used_count)` 的经验响应分布，不强行拟合 `r`。

首次成功游说可提供个体信息。在 `g(p)≠0`、无截断且模型成立时：

$$
\widehat r_i=\frac{w_i^{\mathrm{new}}-w_i^{\mathrm{old}}}{g(p)\gamma_k}.
$$

后续若观测偏差超出校准误差范围，则扩大不确定区间或切回经验表。这是一笔兼具收益和信息的动作，不应为了估计响应而无差别地游说所有节点。

话术选择原则：在响应非负、成本相同、仅数值修正且无额外副作用的条件下，较大的正向修正支配较小修正；产生负增量的话术被排除。此时固定选择最佳话术是合理优化，不需要让 LLM 每次重新猜编号。未确认上述条件时，使用校准后的响应表选择。

### 6.3 固定图下，游说分配可以比一般贪心更精确

当图结构固定、`h` 不变、每个节点的响应序列已知且非负递减、所有游说成本均为 2 时，维护每个节点“下一次可用游说”的增益：

$$
v_{i,k}=h_i\Delta w_{i,k}.
$$

用最大堆反复选择最大的正增益，并把该节点下一次游说入堆。可用次数为 `min(floor(B/2), 剩余环境步数)`。由于各节点的边际序列非增，选择某个后续增益前，其前驱增益一定不会更小，因而满足前序约束。

**在这些限制下，这是固定图游说子问题的最优分配方法**，不是混合动作问题的全局最优方法。个体响应尚未得知、存在顺序副作用、改变图结构或使用非线性目标时，需要重新估计和规划。

还要避免一种无依据的修正：固定线性模型下，不同节点游说的增益可相加，不能因为它们相邻就额外扣一个 VoteRank 式“传播重叠惩罚”。VoteRank 可做候选排序对照，不能覆盖已验证的目标收益。

### 6.4 切边与屏蔽：必须重算整个受影响系统

对候选动作 `a`：

$$
\Delta(a\mid s)=F(\mathcal T(s,a))-F(s).
$$

评估删除后的状态时，要同时处理：存活集合、邻接关系、双方/邻居度数、计分权重、共识自保留参数、连通分量和孤立节点。只减去目标节点的负贡献是不完整的。

候选生成采用“两层”方式：

1. **便宜层**：扫描所有已知合法节点和边，用当前意见、度数、桥接特征、社区差异和粗略分差生成候选；不能只保留负面节点和正负跨社区边。
2. **精算层**：按不同动作类别保留候选，重建反事实模型并计算最终分差。低度数节点、负负边或正面节点也可能有净正收益，应由目标函数判断。

100 节点完全图最多 4,950 条无向边。单次遍历可行，但对每条边、每个情景、每层搜索都重复矩阵求解可能很慢。闭式公式已验证时可全量评估；否则先筛选、缓存并限制规划时间。

### 6.5 用一致情景比较增益

在未知图和响应存在不确定性时，生成 `M` 个与已知事实一致的状态情景。每个情景使用同一个补全状态分别评估执行前后：

$$
\Delta_m(a)=F_m(s_m^a)-F_m(s_m).
$$

不能对执行前和执行后分别随机补图，那会把采样差异误当成动作效果。令 `ω_m` 是验证后的模型/情景权重：

$$
\mu_\Delta(a)=\sum_m\omega_m\Delta_m(a),\qquad
J(a)=\mu_\Delta(a)-\lambda\sigma_\Delta(a).
$$

`J` 是供保守排序的启发式指标，不是未经证明的统计置信下界。对切边和屏蔽可以另外要求所有被保留情景中的增益为正，但这也只对该情景集合成立。官方目标仍是平均原始分，`λ` 的大小必须通过留出种子选择，不能擅自改成最坏情况目标。

## 7. 探索迷雾与预算分配

### 7.1 必须建立的全扫描基线

全扫描消耗如下：

| 阶段 | 扫描成本 | 剩余精神力 | 剩余预算全用于游说的最多次数 | 扫描加游说的动作步数 |
|---|---:|---:|---:|---:|
| 初赛 | 50×0.5=25 | 75 | 37 | 87 |
| 复赛 | 100×0.5=50 | 150 | 75 | 175 |

因此，全扫描占总精神力 25%，而且在每步一次动作的设计下低于 120/250 步。游说次数还受目标节点剩余次数约束；查询、失败和结束回合的额外计数需实测校准。

这使“先获得全图，再精确/近似优化”成为很强且易解释的基线。任务书没有给出干预期持续传播机制，不能用“晚屏蔽就来不及阻断”作为提前删除的理由。

全扫描不必是固定 ID 顺序，更不等于违规静态脚本：每步由 Agent 处理新观测、选择下一个扫描对象并检查计划；全图形成后按实际响应动态重规划。LLM 在初始化和探索检查点参与判断，不能只有无作用的开场调用。

### 7.2 自适应探索作为有实测门槛的增强项

初始可随机扫描 4 个节点（初赛）或 8 个节点（复赛），再进行一轮策略判断；这是起始超参数，不是官方要求。随后同时保留两类候选：

- **前沿候选**：出现在已知邻接表中、连接多个已见区域，或能澄清当前最优动作风险的未扫描节点。
- **盲扫候选**：合法 ID 中尚未见过的节点，用来发现断连分量和前沿策略遗漏的区域。

不能只沿高连接节点扩张，否则会偏向枢纽及其邻居。扫描优先级先用“关联高价值候选、已见连接数、区域覆盖、模型分歧”做便宜筛选，再对少量对象计算信息价值。

### 7.3 信息价值应扣除扫描的机会成本

令 `V(b,B,S)` 是在信念状态 `b`、预算 `B`、剩余步数 `S` 下，后续策略预计得到的最佳终局分。扫描节点 `u` 的价值定义为：

$$
\mathrm{VOI}(u)=
\mathbb E_o\left[V(b^{u,o},B-0.5,S-1)\right]
-V(b,B,S).
$$

VOI（信息价值）比较的是获得信息后的后续最优行动能力，不是扫描直接增加了多少分。右侧已经扣除了资源，不能再机械重复减一次扫描成本。

实际近似流程：对 4–8 个扫描候选，从情景模型采样可能返回值；按假设观测更新知识；运行一个短的后续规划；平均得到扫描价值。采样数量、候选数和耗时通过开发验证确定。

没有可信情景模型时，不要输出貌似精确的 VOI 数值。此时使用全扫描基线，或将启发式扫描明确标记为启发式。

### 7.4 资源预留与停止

不硬编码“侦察 30%、屏蔽 40%、游说 30%”。按当前候选动作和剩余预算动态决策：

1. 扫描后仍须留得出至少一个有意义的后续干预方案；否则扫描通常没有分数收益。
2. 一次屏蔽成本 5，应与同预算下可实现的游说/切边组合比较，不只与一个动作比较。
3. 剩余预算低于 2、且没有其他可产生收益的后续动作时，继续扫描通常不会提高终局分，优先停机保留精神力。
4. 所有后续可行计划的预期收益均非正、或达到计数安全边界时，主动停止；不能把预算耗尽当成唯一停止条件。

全扫描是要被实验证明可以超越的基线。自适应扫描在验证集上的平均分、低分比例和熔断率不优于它，就保留全扫描版本。

## 8. 混合动作的滚动规划

### 8.1 主算法

采用 MPC（模型预测控制）式思路：每轮规划若干步或一个完整预算方案，**只执行第一个动作**，拿到真实返回后重新评估。

推荐从以下可运行逻辑开始：

1. 从黑板生成所有合法的游说、切边、屏蔽和停止候选；扫描由独立的信息价值模块加入。
2. 为当前图计算“保留结构、将剩余预算用于游说”的完成方案，作为当前基准。
3. 对结构动作执行便宜筛选，保留按动作类别分散的候选。
4. 搜索少量结构动作序列；对每个序列形成的新图，重新计算影响系数，再填充剩余预算的游说方案。
5. 比较这些**完整预算方案的最终得分**，而不是只比较第一步的 `Δ/cost`。
6. 把候选及不确定性提交给 LLM 进行策略判断；LLM 可选候选、要求补扫或提出新的结构组合。
7. 任何新增方案都需经过同一个数值评估与合法性校验，随后只执行首个动作。

这会显式比较“花 5 屏蔽后还能做什么”与“保留节点，把这 5 用于其他行动”的差别。不会先删掉一个准备反复游说的节点，也不会把游说后又被删除节点的收益算进最终结果。

### 8.2 有界束搜索

Beam search（束搜索）保留有限数量的较优计划。建议起始配置：结构搜索深度 2、宽度 4、每轮精算结构候选约 12 个；确认时间允许后再试深度 3。所有数值是调参起点，不是已验证最优配置。

每个搜索状态包括：

~~~text
剩余节点与边、倾向和剩余游说次数
剩余精神力、剩余环境步数
动作序列、预测总分、模型分歧
完成此计划所需的后续资源
~~~

处理规则：

- 每个状态都允许停止，并比较其游说完成方案；不强迫计划必须到达搜索深度。
- 同一屏蔽集合、切边集合和游说次数/倾向状态可去重；若顺序影响响应，则不能只按动作集合去重。
- 一次候选动作后重算度数、分量和 `h`；不能沿用原图分数。
- 排序时兼顾总增益、风险和后续预算，不能认为收益/成本贪心对混合动作有全局最优保证。
- 简单版只执行单步可信正收益的结构动作。增强版若考虑首步负收益、组合正收益的计划，必须提前预留完整预算和步数，并验证整个可执行组合，不能只看乐观终点。

情景评估应使用**同一个当前可执行的计划**在各情景上计算。不能在每个情景里偷看完整未知状态、各自选最优动作后再平均，并将其当成当前 Agent 可实现的收益。需要模拟“未来观测后再决策”时，必须显式使用观测分支更新信念。

### 8.3 计算成本控制

50/100 节点的一次线性求解通常不构成算法规模瓶颈，但“候选数×情景数×搜索树×回合数”会放大成本。实现以下限制：

- 相同拓扑与模型参数缓存 `h`；仅倾向变化且无非线性时无需再次求解。
- 结构动作只重新计算受影响分量；分量权重若有全图归一化，必须同步更新相关总量。
- 已确认特殊闭式公式时启用快速路径；否则使用 `solve`，不显式求逆。
- 无模型不确定性时只算一个模型；必要时从 8 个情景起步，分歧很大再增加。
- 设定评估次数和墙钟双上限，超出即返回已完成评估的最佳方案。实际阈值由正式机器或接近的 CPU 测试确定。

A*（A 星搜索）只有在具备可靠的收益上界/可采纳启发函数时才值得进一步考虑。当前混合动作和未知图不具备现成保证，优先采用易中断、可审计的有限束搜索。

## 9. LLM 如何真正参与决策

### 9.1 职责与输入

LLM 不负责手算特征向量或逐项乘加。它负责：

1. 根据已知范围和候选分歧，选择继续探索、执行干预或结束。
2. 在收益、风险、信息价值存在冲突时选择策略，提出值得补算的节点或动作组合。
3. 当人设与实际响应不一致、接口返回异常或结构计划失效时，调整后续策略。
4. 把有证据的失败总结成短规则，在本局剩余回合中使用。

提供给模型的上下文包括：当前阶段、资源余量、观测覆盖率、重要未知项、少量图特征、最多约 8–12 个候选及其估计分差、当前策略、最近几次真实反馈。全图保存在 Python 中，不必每轮粘贴完整历史和全部邻接矩阵。

候选之间应保留有意义的选择，例如“收益略高但结构模型分歧大”“先花 0.5 消除不确定性”“稳定的游说完成方案”。如果程序始终强行选择同一个确定答案，再让 LLM 解释一遍，就无法证明 LLM 的决策价值。

### 9.2 结构化输出协议

下面是**协议格式示例，数值及候选 ID 都是假设值**：

~~~json
{
  "state_version": 17,
  "mode": "intervene",
  "candidate_id": "comm_12_p1",
  "reason_code": "positive_gain_lower_model_disagreement",
  "evidence_ids": ["scan_12_s14", "response_12_s16"],
  "request_replan_after": "new_observation"
}
~~~

LLM 选择已由程序定义参数的 `candidate_id`，避免模型手写错误节点、费用或收益。允许额外使用 `request_analysis` 提议一个新候选，但不能直接绕过求解和执行校验。

解析至少检查：JSON 结构、键值类型、状态版本、候选存在性、目标存活状态、必要扫描条件、边存在性、游说剩余次数、话术范围、预算和计数余量。旧状态的正确动作也可能已经失效，不能只检验 JSON 能否解析。

### 9.3 提示词设计原则

指挥 Agent 的模板可以采用下面的简短指令结构：

~~~text
目标：在资源限制内最大化官方终局加权援助意愿。
已观察事实、模型估计、未确认机制分别给出，不得混用。
从候选中选择下一动作，或请求一次有价值的补充分析。
比较剩余预算下的完整方案，不仅看目标的负面程度或度数。
若建议补扫，说明它会改变哪项决策；若建议删除，检查权重损失。
返回指定 JSON，并用 evidence_ids 指向输入中的证据。
没有可行正收益计划时可以停止。
~~~

收益数值由程序提供，LLM 的解释不覆盖它们。输出简短决策依据即可，不要求长篇内部推理，也不靠自由生成的游说文本改变预设话术效果。

### 9.4 合理调用，而非人为限制为 1–5 次

题目没有“LLM 只能调用 1–5 次”的要求。可将**每个决策步最多一次常规 LLM 调用**作为清晰的对照：全扫描加游说的 87/175 个动作，在没有额外重试等调用时，分别低于 120/250 上限。

官方示例式的“指挥一次，再侦察/执行一次”约为每步两次推理。如果照此运行上述完整序列，约需 174/350 次，可能先触发 LLM 熔断。问题在调用结构与实际价值，不在于 LLM 不适合决策。

建议正式比较两个模式：

- **逐步决策模式**：每步一次 LLM，适合作为能力与调用开销的明确基线。
- **事件触发模式**：初始化、每 4 次左右新扫描、重要响应偏差、结构操作前后、策略阶段切换时调用。已确认的支配性游说序列可以形成短计划，但每次动作后仍由程序校验和更新，异常立即重规划。

不预先宣称哪个模式分数更高。若增加调用能稳定提高平均原始分，就应使用；若只是重复解释同一个选择，就减少。相同总分时才依据规则优先减少调用。

### 9.5 调用计数与失败处理

所有 Agent 共用一个本地调用门控，在每次显式调用注入的 `llm` 前记账。直接复用官方实例，不创建自己的线上模型客户端，不硬编码 API Key。

推荐初始安全余量：环境 Step 预留 3，LLM 调用预留 5，即本地上界分别设为 117/115（初赛）、247/245（复赛）；如果框架还有确定的额外调用，继续扣除。正式计数口径有变化时同步调整。

框架的三次重试需要显式处理：可以在参赛 Agent 中采用一次 `Prompt.send_prompt()` 加严格 JSON 解析的有界决策方法，也可以自行扩展 casevo 的链步骤；无需修改主办方注入实例和服务配置。失败后使用已评估的合法备用候选，最多进行一次有预算的修复请求。

本地计数能精确覆盖参赛代码发出的显式调用；**无法自动观察注入实例内部隐藏的 HTTP 重试**。若正式后端按这些请求计数，需要主办方提供口径或可观测计数，不能声称外层门控已解决一切计数问题。

casevo 的默认记忆工厂会获取 `get_lang_embedding()`；接口兼容性需要启动验证。本题状态很小，使用自有结构化字典与短日志即可，不主动进行每步向量化检索和长篇反思，避免引入额外外部调用。[记忆实现](https://github.com/rgCASS/casevo/blob/d3b8d1f81fe0b3d41ff80908351bd5ebd6809155/src/casevo/memory.py)、[提示词调用路径](https://github.com/rgCASS/casevo/blob/d3b8d1f81fe0b3d41ff80908351bd5ebd6809155/src/casevo/prompt.py)

## 10. 代码组织与接口落地

### 10.1 提交包与本地开发区

正式 ZIP 根目录只放任务书要求的项目：

| 路径 | 内容 |
|---|---|
| `config.json` | `person` 三角色配置；参赛侧需要的阶段/策略配置可放在自定义字段，由主类自己读取 |
| `starnet_model.py` | `ParticipantSquadModel`、三个 Agent、状态与规划工具类；严格三项结构下可在此文件内分区组织 |
| `prompt/commander.txt` | 指挥 Agent 决策模板 |
| `prompt/review.txt` | 异常与重要策略变更复核模板 |
| `prompt/reflect.txt` | 满足当前 casevo 默认初始化所需模板；不代表每回合都调用反思 |

ZIP 不能再套一层 `team_submission/`。本地测试驱动、校准种子、环境代理、个人模型配置、分析日志和开发依赖锁不打入这三项提交内容。若主办方明确允许额外辅助模块，可以拆分，不能擅自假设评测器一定接受扩展目录。

阶段配置必须能明确选择 `n_nodes=50/100`、`initial_budget=100/200` 和对应上限。正式构造接口没有保证提供节点数查询方法，因此不要从观察到的最大 ID 或当前预算武断推断阶段。4 节点自定义测试由本地测试配置显式指定，不进入正式默认值。

### 10.2 框架接入骨架

下面是**实现接口骨架**，帮助明确编排边界；`Knowledge`、三个 Agent 和规划器的方法按本文件前述定义实现后才能运行，不是完成的提交代码。

~~~python
from pathlib import Path
import networkx as nx
from casevo import ModelBase, AgentBase


class ParticipantSquadModel(ModelBase):
    def __init__(self, host_env, person_list, llm):
        agent_graph = nx.Graph([(0, 1), (0, 2)])
        prompt_dir = str(Path(__file__).resolve().parent / "prompt")
        super().__init__(agent_graph, llm, prompt_path=prompt_dir)
        self.env = host_env
        self.done = False
        self.outer_steps = 0
        self.knowledge = Knowledge.from_submission_config(__file__)

        self.commander = CommanderAgent(0, self, person_list[0], None)
        self.analyst = ScoutAnalystAgent(1, self, person_list[1], None)
        self.executor = ExecutorAgent(2, self, person_list[2], None)
        for agent in (self.commander, self.analyst, self.executor):
            self.add_agent(agent, agent.unique_id)

    def step(self):
        if self.done:
            return 1
        self.outer_steps += 1
        try:
            self.knowledge.sync_budget(self.env.get_remaining_budget())
            if self.knowledge.should_stop_before_decision(self.outer_steps):
                self.done = True
                return 1

            snapshot = self.knowledge.snapshot()
            proposal = self.analyst.propose(snapshot)
            decision = self.commander.choose_or_follow_valid_plan(proposal)
            action = self.executor.validate_or_fallback(decision, proposal)

            if action.is_stop:
                self.done = True
                return 1

            result = self.executor.execute_one(action, self.env)
            self.knowledge.apply_verified_result(action, result)
            self.knowledge.invalidate_affected_plans(action, result)
            return 0
        finally:
            self.schedule.time += 1
            self.schedule.steps += 1
~~~

这里由主类显式按分析、指挥、执行的顺序编排，不再调用 `schedule.step()` 让相同角色重复执行。Agent 自身仍需实现职责方法和适配的 `step()`；casevo 的 Agent 注册、Prompt 和 LLM 调用要实际发生。[AgentBase](https://github.com/rgCASS/casevo/blob/d3b8d1f81fe0b3d41ff80908351bd5ebd6809155/src/casevo/agent_base.py)

生产实现还需要给各模块添加有界异常处理：规划异常采用已知合法动作；LLM 异常不导致无界重试；环境调用结果不明确时进入核对状态；无法继续可靠执行时置 `done=True` 并返回 1。不得用一个吞掉所有错误的空 `except` 伪装正常完成。

### 10.3 执行器的硬约束

- 每步最多一个真实付费动作；数值反事实全部在本地状态副本上完成，不调用环境执行假想动作。
- 节点 ID 为阶段范围内的整数。正式版游说和屏蔽要求目标已扫描且存活；切边要求两端已扫描、连线已知有效。
- `prompt_id` 只能为允许值；每个节点依据已知 `comm_left` 校验。预算不足时拒绝动作。
- 对不同接口分别判断成功，只有明确成功才更改黑板。费用的最终事实以环境返回/公开预算查询为准。
- 主动停止返回非 0；不调用 `end_turn()`、`_deduct_budget()`、私有图字段或正式接口未授权的结算功能。
- 所有可变状态属于当前模型实例；新宇宙重新初始化，避免节点信息、游说次数或策略缓存跨种子污染。

### 10.4 本地启动验证的实际要求

先锁定主办方运行环境；当前源码至少要求 Python ≥3.11、Mesa 2.4.0。显式检查 casevo、NetworkX、Jinja2、ChromaDB 和采用的 NumPy/SciPy 是否可用，不仅照搬 SDK README 的三项安装命令。

先用**本地测试替身**验证三角色初始化、提示词加载、一次决策、一次动作和正常停机；测试 LLM 要实现当前 `LLM_INTERFACE` 所需接口。替身只用于开发测试，正式始终使用 `__init__` 注入的 `llm`。[LLM 接口](https://github.com/rgCASS/casevo/blob/d3b8d1f81fe0b3d41ff80908351bd5ebd6809155/src/casevo/llm_interface.py)

随后使用新建的官方开发会话，删除教学动作后，先验证 SDK 的真实返回格式，再跑完整策略。不要把“导入成功”“数值 Mock 跑通”“正式环境得分提高”当作同一种验证。

## 11. 评测、消融与验收

### 11.1 三层验证，分别报告

**第一层：协议和框架。**验证构造签名、三个 Agent 注册、提示词相对路径、预算同步、`step()` 返回码、一次动作限制、JSON 解析、失败回退，以及两个熔断计数器。覆盖 `comm_left=0`、预算恰好够/不足、空图、孤立点、动作目标已被删除和返回状态无法判定等会改变执行结果的边界。

**第二层：数值模型。**用手算微型图和独立实现比较得分、影响系数与动作分差。模型拟合完成后在未参与拟合的结构干预图上验证；如果官方返回有舍入、随机迭代或固定轮数，容差必须依据这些实际语义设置。模型偏差足以改变最优动作排序时，不能启用“精确收益”标签。

**第三层：策略泛化。**所有待比较策略使用完全相同的开发种子，每次从未被教学动作修改的新会话开始，统一精神力、Step 和 LLM 上限。自然演化基准需要独立无干预会话，不能复用被干预后的对象。

### 11.2 测试种子设计

先用 24 个快筛种子：6 类拓扑×2 个规模×2 次重复。最终保留候选在独立的 120 个验证种子上比较：6 类拓扑×2 个规模×10 次重复；调参数据另行生成，不在这 120 个验证种子上反复试参数。

建议六类拓扑为：ER 随机图、BA 枢纽图、WS 小世界图、SBM 社区图、断连/孤立点图、星形与社区桥组合图。它们是开发压力测试，不是假定隐藏种子的生成分布已知。

人设和倾向覆盖：随机分布、负面集中于枢纽、负面集中于跨社区位置、正面核心加负面外围，以及同人设不同响应。强度和范围必须符合自定义种子的校验规则。

另外执行两类泛化检查：

- **ID 重排**：保留同一图的结构和属性，仅随机置换节点编号，检查策略是否依赖编号巧合。
- **分布偏移**：改变图密度、社区强度、人设比例和响应离散程度，观察平均分和负提升比例是否恶化。

对于包含 LLM 随机性的最终两三个候选，每个种子重复至少 3 次。统计时先对同种子的重复取平均，再做种子层面的配对比较，避免把同种子的重复试验当成独立拓扑样本。

### 11.3 必须比较的基线

| 版本 | 策略 | 回答的问题 |
|---|---|---|
| B0 | 无干预自然演化 | 是否实际提高了终局分数 |
| B1 | 全扫描＋度数/响应启发式游说，真实 casevo＋LLM 编排 | 可执行的简单方案有多强 |
| B2 | 全扫描＋已校准目标影响系数＋游说分配 | 用真实目标替代通用中心性能否提升 |
| B3 | B2＋单步切边/屏蔽反事实 | 结构动作是否有净收益 |
| B4 | B3＋结构束搜索＋剩余游说完成方案 | 联合规划是否优于单步贪心 |
| B5 | B4＋自适应扫描和响应在线更新 | 节省扫描预算是否超过信息损失 |

在最终方案上只改变一个因素做消融：去掉结构反事实、去掉不确定性惩罚、改成全扫描、事件触发 LLM 改成逐步 LLM。去掉 LLM 的纯算法版本只作为**内部研究对照**，用于量化模型决策的贡献，不作为声称满足赛题融合要求的提交版本。

可以在极小图上做穷举最优解，检查有限搜索的损失；全知、免费读图的 Oracle（理想上界）与实际 Agent 的信息成本不同，不能当作同条件公平对照。

### 11.4 指标与晋级门槛

主指标：

$$
\mathrm{PlayerAvg}=\frac1M\sum_{j=1}^{M}F_j,
\qquad
\overline{\Delta}=\frac1M\sum_{j=1}^{M}(F_j-F_j^{\mathrm{natural}}).
$$

同时记录：低于自然演化的种子比例、低分位结果、剩余预算、LLM 调用数、Step、P95 运行时间、非法动作数、重复付费动作数、熔断数，以及三类干预各自的成本和预估收益偏差。

上线门槛建议：

1. 协议测试无崩溃，验证集中无非法动作和主动可避免的熔断。
2. 同种子配对分差优于当前最佳方案；可用种子级 Bootstrap（自助重采样）报告均值差的区间。
3. 增加复杂度的模块须有实测收益。收益不稳定，就保留较简单的已验证版本。
4. 真实得分相同时，按官方规则优先剩余精神力更多、随后 API 更少的版本。

不要拿单个种子的高分、代理模型的预测分或未经实际运行的“预计提升 20%”作为成绩证据。

## 12. 实施顺序与交付门槛

### 阶段 P0：打通协议和机制校准

完成 SDK 差异修复、版本锁定、构造与终止测试、公开 API 返回格式验证，以及第 5.1 节的核心微型实验。

交付：接口约定、可复现开发驱动、校准数据、评分模型候选及误差报告。若精确机制仍不能确认，保持结构干预关闭，进入保守游说基线；不能假装校准已完成。

### 阶段 P1：完成强基线

实现三 Agent、状态黑板、全扫描、固定图游说收益分配、逐步反馈更新、LLM 有界调用和主动停止。

交付：B1/B2 的同种子成绩、成本与失败日志。确认完整 50/100 节点规模能在正式资源限制内结束，再推进复杂优化。

### 阶段 P2：加入有收益证据的结构规划

加入切边/屏蔽反事实、按动作类型的候选覆盖、两层结构束搜索和剩余游说完成方案；每次结构变化后重算影响系数。

交付：B3/B4 配对实验，尤其检查“删除负面中心损伤正面邻居”“切桥造成有利传播丢失”“游说后删除目标”“结构组合需要完整配套预算”等反例。

### 阶段 P3：优化探索和 LLM 决策

加入前沿与盲扫混合、响应在线更新、少量情景评估和事件触发推理，比较 B5 与全扫描版本。

交付：LLM 和自适应探索的消融结果。数据不支持增益时不默认启用；优先保留已验证的分数和稳定性。

### 阶段 P4：冻结并提交

按 5 个窗口的官方时间表保留可回退版本。每次截止前做独立干净会话测试、ZIP 根目录检查和预算/调用计数复查。记录提交版本、配置和本地成绩；实际截止日期以官方公告为准，任务书未提供具体日期。

第一份推荐提交形态是 **P1 的强基线＋已校准且经过留出验证的 P2 功能**；P3 只在验证收益明确时加入。不以堆叠 Agent 数量或复杂算法数量作为完成标准。

### 13.4 2026-09-06：P2.1 机制辨识与失效关闭的重拟合

为解决上述误差，新增 29 个公开 API 自定义微图会话，覆盖路径端点/内部、三角形顶点、星形中心/叶子的正负单点脉冲，以及切边、屏蔽和一次游说。所有会话可比。数据支持候选

$$
\widehat F(G,w)=\sum_{C\in\mathcal C(G)}
\frac{|C|}{\sum_{i\in C}(d_i+1)}
\sum_{i\in C}(d_i+1)w_i.
$$

在该批数据上 MAE 为 `0.00094`、最大误差为 `0.00429`；以它事后回放旧 V1 记录时，gate Spearman 为 `1.0000`、归一化 MAE 中位数为 `0.00182%`。这解释了为何旧的未归一化 degree 模型在路径、三角形和星形失配。

然而 V1 的三个 split 重用所有图族，只替换意见布局；候选又产生于旧 gate 失败之后。两者均不满足真正的拓扑留出验证。因此代码新增 topology-holdout 门禁，重分析仍是 `gate_passed=false`；默认 B1 和未冻结的 `CalibrationProfile` 不变。下一步必须按拓扑不相交的新 P2.2 清单重复采集与验证，不能凭本段结果启用 CMG 或结构动作。详细方案、数据索引和结果见 [`p2-settlement-refit-v2-20260906.md`](../03_experiments/p2-settlement-refit-v2-20260906.md)。

### 13.5 2026-09-06：P2.2 拓扑留出结算器门禁通过
