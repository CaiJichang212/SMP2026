# P8 optimization and release evidence

Branch: `optimize-score900-p8-20260913`. The enabled candidate is P8
`conservative`, selected by a preregistered local mean-score criterion on fresh
data. Official hidden-seed **>900 is not established**; no local-to-platform

## What changed

First-action replay isolated response-estimation error in three known P7 losses.
Their constant-response predictions were +1.42 to +3.26, but actual paired losses
were approximately 12--49 points. Fixing subsequent actions to public greedy
preserved these losses, so later replanning was not an additional net cause in
those selected cases. These diagnostics are not independent validation.

P8 includes up to four legal choices: the current baseline, a budget-plan
structural first action, the largest immediate structural gain, and an untried
communication. Communication reaches heterogeneous-response evaluation even
when its constant-mean screen is neutral, preserving the possibility of learning
a useful response. Scenarios are salted from the initial complete public graph,
not experiment seed IDs or private response factors. Known responses become
visible only after successful public actions.

`conservative` requires positive mean and nonnegative minimum gain across five
paired assumed-response scenarios. The more restrictive `audited` comparator
adds eight unused scenarios for the selected action. Both compare complete
public-greedy continuations. These finite scenarios do not prove nonnegative
actual gain in every possible world.

The CaseVO commander can choose the validated proposal or the baseline. The
existing budget, node, edge, communication-quota, prompt-ID, state-version, and
LLM-call guards remain in the execution path. Planning errors retain the
baseline; invalid or failed LLM calls are counted and use a validated fallback.
Hypothetical state is separate from factual Blackboard.

## Fresh mean-objective protocol

The competition optimizes a mean. Requiring every hand-selected family's
finite-sample mean to be nonnegative is a stronger objective. Rather than
relabelling the old confirmation, commit `70e2fbc` preregistered a separate
701--705 comparison before those data were read. The policy stayed frozen at
`47064c6`, SHA-256
`56709076b9c89d7934899f046c20198f569575b165871adfc9055e49269500b0`.

The new protocol fixes 22 family strata and bootstraps paired repetitions
within each family. Its additional composition stress minimizes gain over
family proportions between `0.5/K` and `2/K`, summing to one. This range is a
declared sensitivity assumption, not knowledge of official sampling weights.
For each of two arms, the 2.5th bootstrap percentile of stressed gain must be
positive. This uses a one-sided 97.5% bound per arm with a Bonferroni intention;
bootstrap coverage is approximate, not an exact finite-sample guarantee.

All cohorts must be complete, use identical seeds/baselines and a frozen policy
hash, and have zero failed actions or resource violations. Three response-shift
group means must separately be nonnegative. That empirical shift check is not
a proof of population noninferiority. Highest standard mean among passing arms
determines the selected candidate.

data do not establish that conservative is statistically superior to audited;

Raw-score ties showed no worse remaining budget or action count in the selected

## Runtime and numerical verification

Two real local-LLM CaseVO trials on the development hub case completed with
75/75 accepted calls each, zero fallbacks, zero transport errors, and zero
action failures. Conservative reproduced `274.7650 → 303.6876`; audited
reproduced `274.7650 → 285.5288`. These are local-model protocol checks, not
official GLM hidden-seed evaluations. Algorithm confirmation above was
deterministic; it is not a 110-seed real-LLM benchmark.

The generated entry was also checked with its actual enabled configuration,
with deliberately missing qualification, and with test-only qualifications.
Enabled and fallback scores matched the corresponding development runs.
In-memory qualification patches used by the smoke test never modify files or
qualify a policy for release.

The actual generated single file then completed a real-LLM paired run on the
official public custom-seed sandbox: baseline 274.82 and enabled P8 303.74,
gain +28.92. Each fresh session had 75 accepted calls to the configured local
`gpt-5.6-luna`, zero fallbacks, zero transport/action failures, and zero public
response error versus replay. The new model used `P8RuntimeController`; the
control disabled qualification only in memory. The generated model bytes match
the packaged runtime. An earlier attempt failed at result logging because a
model-name field was read from the wrong adapter layer; it was excluded and
rerun after fixing metadata validation and incremental result persistence.

Equivalent acceleration removes unused communication settlement calls and
caches topology/action coefficients. It preserves floating-point accumulation
order and stores no opinions in the persistent caches. The topology cache is
bounded at 128 entries; action tables retain at most 16 parent topologies, with
legal actions bounded by their nodes and edges. Hundreds of state, action, and
candidate comparisons matched the reference exactly. A 200-candidate-set
microbenchmark improved from 36.7357s to 9.4887s (about 3.87x); concurrent load
means this is not an official latency guarantee.

Two slow confirmation jobs resumed after this equivalent acceleration. All
58 checkpointed completed rows were verified unchanged by hash; interrupted
in-progress cases restarted from their original seed. No case was dropped.
Checkpoint evidence is in `p8-fast-resume-checkpoints-20260913.json`.

The local `run_baseline_openai.py` adapter now preserves a qualified P8
controller when applying debugging limits; it previously replaced every
submission controller with the baseline type. It falls back for a different
resource envelope or a conflicting local guard experiment. Archive comparison
also records the effective P8 mode, avoiding an ambiguous identical base config.

The main agent and three subagents used `autoresearch` and `experimental-design`
to separate diagnosis, development, confirmation, and deployment. Subagent
service interruptions were handled by continuing the numerical jobs directly.
Procedural skill reference: Kassis, Agarwal, He, Patel, and Brueckner (2026),
*Scientific Agent Skills: A Library of Procedural Knowledge for Research Agents*,
https://doi.org/10.48550/arXiv.2609.00065 (metadata checked earlier in this session).

```bash
uv run python scripts/check_p8_submission.py --real --remote
uv run python scripts/package_submission.py --name starnet-p8-mean-20260913.zip
```
