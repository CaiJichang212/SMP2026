# P7 research and preregistered experiment design

Branch: `optimize-score900-p7-20260912`, baseline `373103f`.
User-reported official score: **761.9467**, objective **>900**. Local custom-seed
scores and the hidden-seed platform score are separate measurements. This work
does not establish a conversion between them.

## Evidence and hypotheses

The existing P6 50-node confirmation matrix improved by 6.4524 points on average,
but four of thirteen family means regressed. It did not pass promotion. Real LLM
versus forced-fallback archive tests previously produced identical final scores
on six custom seeds. Candidate selection and budget use are therefore the focus.

H1: requiring a budget-complete structural plan to outperform an unchanged
topology under low, mean, and high unobserved-response scenarios can reject
premature deletion of useful communication targets. Known first responses come
only from successful public action returns. The three constant scenarios are
stress scenarios, not a confidence interval or exhaustive robustness guarantee.

H2: evaluating candidate first actions followed by the current complete policy
can account for future structural actions which a persuasion-only terminal tail
omits. Paired rollouts share scenario samples, and each simulated policy observes
a response only after its simulated communication. Finite model-based scenarios
do not guarantee improvement in the real environment.

H3: new geometric, barbell, lollipop, random-tree, and bipartite graphs, with ID
permutations and separate response strata, can expose dependence on the old
benchmark distribution. Hindsight persuasion diagnostics quantify a restricted
subproblem, not an upper bound over all legal interventions.

All initial variants, development/confirmation repetition numbers, and gates are
fixed in `experiments/manifests/p7-robust-rollout-20260912.json`. Confirmation
data may be evaluated only after selecting and freezing a development winner.
Historical `independent` and `holdout` block names do not make reused families
unseen. Threshold tuning after confirmation would require a fresh confirmation
block. Cases must not be removed to obtain a mean above 900.

## Online sources checked

Live GitHub and arXiv structured API requests succeeded on 2026-09-12.

- Official SDK repository: <https://github.com/raoneng26/SMP2026>, latest returned
  commit `75e896fb137d850f76c44eab2f14c38b6df59d3a`, dated 2026-09-04.
- *Voting-based Opinion Maximization*, <https://arxiv.org/abs/2209.06756>:
  abstract states several objectives are non-submodular. This supports testing
  complete budget consequences; its guarantees are not transferred to this task.
- *Manipulating Collective Opinion through Social Network Intervention*,
  <https://arxiv.org/abs/2511.12444>: the abstract describes unintended shifts
  from reduced interaction, motivating explicit downside checks.
- *Rollout Sampling Approximate Policy Iteration*,
  <https://arxiv.org/abs/0805.2027>: motivates bounded sampling for comparing
  candidate policies. This work uses the idea, not a reproduction of that paper.
- *Performance Bounds for Rollout Policies in Stochastic Shortest Path Problems*,
  <https://arxiv.org/abs/2605.22965>: the abstract connects rollout error to value
  approximation and model mismatch. No theorem from it is asserted here.

The papers above were checked at abstract/metadata level, not fully reproduced.

## Skills used

Installed `autoresearch` from GitHub's `awesome-copilot` collection (search
reported 3.3K installs; GitHub API reported 38,928 repository stars) and
`experimental-design` from K-Dense (831 installs; 44,565 repository stars).
These popularity measurements are retrieval-time signals, not validation of
scientific correctness. Installation used the provided skill-installer script.

The first skill supplies hypothesis/change/measurement/keep-or-reject iteration;
the second supplies paired blocking, correct replication units, and a frozen
confirmation design. Existing task authorization supplies setup parameters.
Repository instructions override the skill's hard-reset and root-log examples:
experiments remain isolated, failures stay disabled, and reports/manifests use
the repository's established locations. No extra runtime dependency is needed.
